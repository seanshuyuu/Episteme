## 3. 代码结构

```
src/
  Episteme.slnx
  Episteme.Core/                    零 NuGet 依赖，纯领域逻辑
    Entities.cs                    Space/Node/ContentType/Document/Part/Annotation/
                                   Blob/Tree/Commit/Ref/AuditLog + Jsonx/Ids
    SchemaEngine.cs                FieldDef / ContentTypeDefinition、CheckDefinition、
                                   Validate、Render、FieldSchema、ToolInputSchema、Migrate
    Versioning.cs                  Canonical sha256 规范化、TreeStore、DiffService（LCS 行级）
    McpTools.cs                    ToolRegistry：20 静态工具 + 按类型派生 query/create/update
  Episteme.Server/                ASP.NET Core 10 Web（EF Core 10 + SQLite）
    EpistemeDbContext.cs           11 张表、唯一索引、级联
    EpistemeService.cs             P1：空间/目录/Schema/文档/Part/标注/检索
    EpistemeService.Version.cs     P2：树快照、Commit 事务、diff/revert/merge/blame、工具清单
    Endpoints.cs                  docs/06 REST 全表 + 统一错误/响应头
    McpEndpoint.cs                initialize / tools / resources + 工具分发（含动态工具）
    Program.cs / wwwroot/         静态 SPA：index.html + app.css + app.js + tokens.json
deploy/                           Dockerfile、docker-compose.yml、.env
tests/                            api_smoke.py（37 项）、ui_smoke.js（16 项）
```

**统一写入事务**（`PersistAsync`）：实体变更 → `SaveChanges` → 幂等检查（命中则回滚整笔变更并返回原 Commit）→ 构造 Blob/Tree → 插入 Commit → 移动 Ref → 写 AuditLog → 提交。REST 与 MCP 调用同一个 `EpistemeService`，不存在两套逻辑。

## 6. 回归过程中发现并修复的真实缺陷

| # | 缺陷 | 根因 | 修复 |
|---|---|---|---|
| 1 | 定义含 `reviewedBy` / `internalCost` 的类型被拒 `SCHEMA_VALIDATION` | 字段 key 正则只接受 `a-z0-9_`，与 `design/schemas/*.json` 的 camelCase 契约冲突 | 拆分为 `SlugRe`（类型 slug 保持小写下划线）与 `KeyRe`（字段 key 允许 camelCase） |
| 2 | 第二次创建空间报 `INTERNAL`（DB 保存失败） | 空树哈希全局相同，`trees` 主键跨空间冲突；同批次相同内容 Blob 也会重复插入 | 树哈希纳入 `spaceId`（每个 Space 独立 DAG）+ `HashSet` 本地 Blob 去重 |
| 3 | UI 写入的 Commit `source` 被记为 `api` | `WriteContext.From` 未读取请求体 `source` | 支持白名单内 `ui/api/mcp/import/schema/system` 透传 |
| 4 | revert 报 `UNIQUE constraint failed: Parts.DocumentId, Parts.Ord` | 旧 Parts 未先落库删除就重建同 docId + 同 Ord 的 Part | 显式加载并删除 Annotation/Part/Document，`SaveChanges` 后再重建 |
| 5 | 动态表单不渲染、创建按钮被禁用 | `render` 契约缺 `contentType` 字段，前端误判「未绑定类型」 | `SchemaEngine.Render` 输出 `contentType` |

构建期另有 1 处局部变量重名（`canonical`）编译错误，已修正；同时在构建命令中补 `set -o pipefail`，避免管道吞掉失败退出码导致旧镜像被误重启。

## 7. 明确边界与简化（诚实清单）

以下是**与规格的偏离**，需要在进入下一阶段时补齐，不应被误认为已完成：

1. **Web UI 形态**：本轮用 `wwwroot` 下的原生 SPA（零构建、零依赖）而非规格 §6 的 Blazor Interactive Server。理由是当前宿主无法运行 Chromium/Playwright，原生页可用 jsdom 做真实点击回归、避免 `blazor.web.js` 静态资源类故障；后端仍是 ASP.NET Core。后续可在不动 REST/MCP 的前提下替换为 Blazor 通用渲染器。
2. **数据库**：用 EF Core + SQLite（开发态单容器即可跑），未接 PostgreSQL 17 / `jsonb` / GIN / `zhparser`；Redis、MinIO 未接入，`toolsVersion` 未做跨实例广播。
3. **鉴权**：简化为 `X-Episteme-Role` 请求头（`owner/editor/viewer/agent`）做 scope 校验；JWT、API Key + HMAC-SHA256、Nonce、Idempotency-Key 请求头（`idempotencyKey` 走 body）、审计签名均未接。
4. **MCP**：自实现最小 JSON-RPC 层，未使用官方 `ModelContextProtocol` C# SDK；`stdio`、SSE 长连接、`notifications/tools/list_changed` 主动推送未实现（客户端可轮询 `toolsVersion`）。
5. **版本 DAG**：Tree 只保存文档快照；Schema / 目录变更会产生 `source=schema` / `api` 的 Commit，但不进入 Tree diff。merge 生成单 parent Commit（规格要求双 parent）；blame 返回最近提交归属（简化）；GC、导出真实 git 仓库（当前只返回线性化清单）未实现。
6. **阅读器与标注**：Part 支持 `md/code/pdf/web/attachment` 五种 kind 与文本 diff，但 UI 仅提供 Markdown 文本域；PDF 页面渲染与 `page+rect+textQuote` 锚点、Web 抓取/Readability、Monaco/CodeMirror 均未实现。
7. **抓取安全**：`fetch-worker` 独立网络与 SSRF 白名单未实现（P3）。
8. **Pack / 三端**：`workbench` Pack 安装、旧 16 张表迁移、39 项旧冒烟与 22 项旧交互回归、Avalonia 桌面/Android 均未实现（P4/P5）。旧项目已按用户要求清理，兼容红线不再有可执行对象。
9. **其他规格项**：`PATCH /spaces/{id}`、`GET /parts/{id}/content`、`/packs`、`/fetch`、字段唯一性校验、`ref` 对称引用、视图筛选/排序、Schema 表达式索引、中文全文检索分词等未落地。

## 8. 下一步建议
