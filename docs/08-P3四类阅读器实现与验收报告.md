## 1. 本轮范围

用户在 P1+P2 完成后选择「继续 P3 阅读器」。本轮交付：

| 层 | 内容 |
|---|---|
| Core | `ViewerRegistry` 统一契约与能力矩阵、`PartContent` 文本提取/分页/指纹、`AnchorEngine` 锚点归一化 + 四级回退；`DiffService` 增加标注级差异 |
| Server | Part 写入归一化与类型约束、PDF 原件只读、标注锚点校验与 Commit 归属、快照包含标注、revert 时标注 `partId` 重映射、阅读/导出端点 |
| Web UI | Markdown / Code / PDF / Web 四类阅读器、标注侧栏、版本 ref 切换只读历史快照、一键导出标注笔记 |
| MCP | 新增 `episteme.viewers` / `episteme.read_part` / `episteme.export_notes` 三个静态工具（20 → 23） |
| 部署 | Dockerfile `restore` 拆为独立缓存层；版本号升至 `0.3.0-p3` |

**设计原则**：文档是载体，格式是 Part。一份文档可同时挂 md / code / pdf / web 四类 Part，四类共享同一套 `mount / read / edit / annotate / snapshot / capabilities / destroy` 契约；所有改动（含标记）都进入同一条 Commit 链。

## 2. 统一 Viewer 契约

`GET /api/v1/episteme/viewers` 返回 `contractVersion=1` 与五类媒介描述。未知 kind 降级为 `attachment` 预览，写入时由 Server 拒绝。

| kind | MIME | 可编辑 | 可标注 | 可检索 | 二进制 | 定位主键 | 回退 |
|---|---|---|---|---|---|---|---|
| `md` | `text/markdown` | ✅ | ✅ | ✅ | ❌ | `textQuote.exact` / `blockIndex` / `line` | text-quote |
| `code` | `text/plain` | ✅ | ✅ | ✅ | ❌ | `line` / `lineRange` | line |
| `pdf` | `application/pdf` | ❌ **只读** | ✅ | ✅ | ✅ | `page` (+`rect`) | page-rect |
| `web` | `text/html` | ✅ | ✅ | ✅ | ❌ | `domPath` / `textQuote.exact` | dom-path |
| `attachment` | `application/octet-stream` | ❌ | ✅ | ❌ | ✅ | `offset` / `textQuote` | offset |

Part 写入统一走 `NormalizePart`（`EpistemeService.Parts.cs`）：校正 kind、写 MIME、计算 64 位 sha256 `fingerprint` 写入 `meta` 与 `stats`，并按类型自动推导元数据——Code 统计行数并保留 `language`；PDF 按 `\f` 推导 `pages` 与 `textLayer`；Web 推导 `extractor` / `httpStatus` / `origin=external`。`PUT` 更新时重新计算 `blobHash` 与 `meta`，PDF 若尝试改 `content` 返回 `409 PART_NOT_EDITABLE`。

### 稳健锚点（四级回退）

`AnchorEngine.Normalize` 在写入时校验并补齐 `version / kind / partKind / fingerprint / status / fallback`，拒绝：行号越界、页码 < 1、引文在正文中不存在、web 缺定位信息、未知标记类型（统一 `422`）。合法标记类型：`highlight / underline / note / area / bookmark`。

`AnchorEngine.Resolve` 在读取时按内容指纹判断是否同一版本，逐级降级：

| 级 | 策略 | 条件 | 状态 |
|---|---|---|---|
| L1 | `fingerprint-position` | 指纹一致且 `textPosition` 区间与引文匹配 | `anchored` |
| L2 | `text-quote` | exact → prefix/suffix 消歧 → 空白归一化模糊匹配 | 同版本 `anchored` / 异版本 `relocated` |
| L3 | `page-rect` / `line` / `dom-path` | 页码、行号、DOM 路径仍在有效范围内 | `relocated` |
| L4 | `none` | 全部失效 | `lost` + `ANNOTATION_ANCHOR_LOST`，**在 UI 明示，绝不静默丢弃** |

### 标记进入版本历史

`SnapshotOf` 现在把 `annotations` 一并写入 Tree 快照；`DiffService.Compare` 输出 `DiffItem.Annotations` 标注级差异。新增标注时预生成 `ForcedCommitId` 写入 `anchor.commitId`，保证「锚点归属的 Commit」与「不可变快照」一致。revert 重建历史快照时会删除旧 Annotation/Part/Document 再落库，并按 partId 映射恢复标注，避免唯一索引冲突与标记丢失。

## 3. 新增接口

REST（前缀 `/api/v1/episteme`）：

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/viewers` | 全局 Viewer 契约与能力矩阵 |
| GET | `/spaces/{id}/documents/{docId}/viewers` | 文档级 Part 描述、统计、每 Part 标注、`annotationTotal` / `anchorLost` |
| GET | `/spaces/{id}/documents/{docId}/parts/{partId}?from=&to=&page=&mode=` | 按行区间 / PDF 页码 / Web 纯文本读取 |
| POST | `/spaces/{id}/documents/{docId}/exports/notes` | 跨 Part 汇总标注，导出为一个新 md Part + Commit |
| GET | `/spaces/{id}/documents/{docId}/annotations` | 标注清单，附 `status` / `resolution` / `commitId` |

`GET /documents/{docId}?ref={commitId}` 现在返回快照内的标注，供阅读器切换历史版本（历史版本只读）。

MCP 静态工具由 20 增至 **23**：`episteme.viewers`、`episteme.read_part`、`episteme.export_notes`；`episteme.annotate` 与 `episteme.append_part` 的签名同步补充 `partId` / `anchor` / `partKind` 说明。`toolsVersion` 与字段可见性开关逻辑不变。

## 4. 前端四类阅读器

在原有 Schema 驱动三栏 SPA 上新增「阅读」Tab，点击文档卡片进入：

- **Markdown**：源码 / 预览双模式，源码可编辑并保存到新 Commit。
- **Code**：阅读模式渲染行号 + 轻量正则语法着色（`tok-kw` / `tok-str` / `tok-num`），点行号自动填入锚点行号；源码模式可编辑。
- **PDF**：文本层分页卡片、上一页/下一页、明确「原件只读 · 改动以标记存储」提示；点文本行生成区域锚点。
- **Web**：正文 / 纯文本 / 原文快照三态，顶部显示外部来源与「快照不执行脚本」；可重抓更新 `sourceUri` / `meta`。
- **标注侧栏**：引文、行号、页码、DOM 路径输入，写入后展示 `anchored / relocated / lost` 与命中的回退策略；一键导出标注汇总。
- **版本联动**：ref 下拉切换到历史 Commit 后进入只读态；版本 Tab 仍可查看 Commit 链与 diff。

## 8. 明确边界与简化（诚实清单）

以下是**与 `docs/04` 规格的偏离**，不应被误认为已完成：

1. **PDF 是文本层模式，不是真实 PDF 渲染**：用 `\f` 分页的纯文本模拟文本层，未接 pdf.js，不解析 PDF 二进制，`rect` 只存坐标不绘制高亮框，无缩略图/缩放/搜索高亮。
2. **Web 是快照模式，不是抓取服务**：自研轻量 HTML→纯文本抽取（`readability-lite`），未接 Readability / DOM 序列化；`sourceUri` 只是元数据，**未实现 `fetch-worker`、SSRF 白名单、独立网络命名空间**，`httpStatus` 由调用方提供。
3. **Code 是轻量正则高亮**：未接 Monaco / CodeMirror，无 LSP、折叠、minimap、多语言 grammar。
4. **Markdown 是小型转换器**：非完整 CommonMark/GFM，不支持表格、脚注、数学公式。
5. **锚点 `lost` 只提示不重定位**：尚未提供交互式手动重新锚定；L2 模糊匹配是空白归一化，不是语义相似度。
6. **版本模型仍承接 P2 简化**：merge 单 parent、blame 为最近提交归属、export git 仅线性清单、Schema/目录变更不进 Tree diff。
7. **生产化边界全部保留自 `docs/07 §7`**：SQLite 非 PostgreSQL、无 Redis/MinIO、`X-Episteme-Role` 非 JWT/HMAC/Nonce、原生 SPA 非 Blazor、自实现 JSON-RPC 非官方 MCP SDK、无 SSE/stdio、无 Avalonia 三端。
8. **P4 / P5 未做**：Workbench Pack 安装与旧数据迁移、模板导入导出、三端客户端。

## 9. 下一步建议

优先级从高到低：

1. **补齐真实媒介**：pdf.js 渲染 + 真实 PDF 文本层解析；独立 `fetch-worker` + SSRF 白名单做 Web 抓取；Monaco/CodeMirror 与 Readability。
2. **锚点工程化**：`lost` 标记的交互式重定位、语义模糊匹配、标注迁移到新版快照时的批量复核。
3. **生产化**：PostgreSQL `jsonb`/GIN、Redis 广播、JWT + HMAC + Nonce、Blazor 通用渲染器、官方 MCP SDK 与 SSE/stdio。
4. **P4 / P5**：Pack 安装与迁移、模板生态、Avalonia 三端。
