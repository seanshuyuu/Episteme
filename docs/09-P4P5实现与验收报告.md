## 2. P4 声明式 Pack 契约与实现

### 2.1 契约（`src/Episteme.Core/PackEngine.cs`）

Pack 是**纯声明式 JSON，不含任何可执行代码**：`$schema` / `id` / `name` / `version` / `episteme` / `contentTypes` / `nodes` / `views` / `prompts` / `jobs` / `sampleDocuments`。
`$schema` 固定 `https://episteme.local/schema/pack/v1`。

`PackEngine.Validate` 做静态校验：`id` 正则 `^[a-z][a-z0-9_-]{0,63}$`、版本号、节点路径格式、节点引用的 `contentType` 必须已在 `contentTypes` 中声明、示例文档引用的 `node` / `type` 必须存在；数量上限 `MaxNodes=500` / `MaxContentTypes=200` / `MaxSamples=200`。节点按路径深度排序，保证父目录先于子目录创建。`PackEngine.Summary` 输出目录数、类型数、示例数与校验结果。

### 2.2 内置两套模板

| 文件 | id | 目录 | 内容类型 | 示例文档 |
|---|---|---|---|---|
| `wwwroot/packs/workbench.json` | `workbench` | 15 | 12 | 0 |
| `wwwroot/packs/reading-desk.json` | `pack_reading-desk` | 5 | 4 | 2（覆盖 pdf / md / web / code 四类 Part） |

两份由 `design/schemas/workbench-pack.json` 与 `generic-library.json` 发布而来，补上 `$schema`；`workbench` 内含 11 个 Workbench 模块目录、两大口令、views / prompts / jobs / migration 元数据。`GET /packs` 对每份模板实时跑一次校验并返回 `valid`。

### 2.3 安装（`EpistemeService.Packs.cs`）

- **一个事务**：`ContentType` + `Node` + 可选示例 `Document/Part` + `Blob/Tree/Commit/Ref/AuditLog` 全部经统一 `PersistAsync`，产生**一条 `source=import` 的 Commit**，并 `toolsVersion++`。
- `packId`（内置）与 `pack`（内联 JSON）二选一；Pack 内容的 `id` 是权威，不按文件名查找。
- `dryRun=true`：只返回 `wouldCreate*` 与冲突清单，`commitId=null`，不写库。
- `overwrite=true`：允许覆盖同名对象；否则同名类型/路径返回 `409 PACK_CONFLICT`。
- `includeSamples=true`：同时导入示例文档，示例的 `title` 镜像到内容类型的 `primaryField`，走与正常写入相同的 `SchemaEngine.ApplyDefaults` / `Validate`。
- `idempotencyKey`：重放时短路返回原 Commit，不重复写入、不被冲突检查误拦。
- `POST /packs/export`：把当前空间的目录树、最新 Schema、可选文档导出为可复用的 Pack JSON；`id` 由空间 slug 合法化生成，避免点号 / 中文等非法字符。
- `POST /packs/import`：导入自定义 Pack，复用同一条安装通道。

### 2.4 与版本模型的一致性

`PersistAsync` 先 `SaveChangesAsync` 再 `BuildTreeAsync`，因此安装时新建的目录、类型与示例文档都会进入该 Commit 的快照；`revert` 到安装前提交即可整体撤销一次模板安装。

## 8. 本轮发现并修复的问题

1. **`PackEngine.Str` 可见性**：`internal` 导致 Server 侧 `CS0117`，改为 `public`。
2. **按文件名找不到 Pack**：`GET /packs/pack_reading-desk` 与文件 `reading-desk.json` 不一致；改为遍历 `*.json` 按内容 `id` 匹配，Pack 内容 id 成为权威。
3. **`UNIQUE constraint failed: Nodes.SpaceId, Nodes.Path`**：逐节点 `EnsureParentsAsync` 查不到同一 DbContext 里尚未 `SaveChanges` 的 pending additions；改为 `NeededPaths()` 在内存物化全部声明路径 + 隐式父路径，按深度创建并用 `nodeByPath` 去重。
4. **首次带幂等键被误判为重放**：仅比较幂等键会把第一次写入也当成重放；给 `WriteContext` 增加 `Replayed`，只由 `PersistAsync` 命中重放时置位，`IsReplay` 改为只读该标志。
5. **幂等重放被冲突检查拦成 409**：在冲突检查之前用 `FindIdempotentAsync` 短路返回原 Commit。
6. **导出 `id` 非法**：空间 slug 含点/中文时破坏 Pack 正则；导出时把字符过滤为 `a-z0-9_-`。
7. **`includeSamples` 返回 0 篇示例文档**：新建目录/类型在 `SaveChanges` 前对查询不可见；改为复用内存 `nodeByPath` / `typeRows` 字典，并把示例 `title` 镜像到 `primaryField` 以通过 Schema 校验。修复后 80/81 → 81/81。
8. **Avalonia 12 `AVLN2100`**：`MainWindow.axaml` 的编译绑定缺 `x:DataType`，补 `xmlns:vm` + `x:DataType="vm:MainViewModel"`。
9. **Avalonia 12 `AVLN5001`**：`TextBox.Watermark` 已过时，统一改为 `PlaceholderText`，最终 0 警告。
10. **NuGet 原生包下载超时**：`SkiaSharp.NativeAssets.Linux` 首次 100s 超时；重试成功，并给客户端构建挂持久缓存卷 `episteme-nuget-cache`，后续不再重复下载。

- **P4 旧表迁移**：旧 Workbench 数据已被用户要求清理，无迁移对象；备份与恢复步骤在 `/mnt/work/backups/workbench-cleanup-20261110/RESTORE.md`。
- **模板市场**：仅本地 JSON 目录 + 导入导出，无服务端模板目录 / 版本市场 / 签名校验。
- **stdio MCP**：未实现；桌面端通过 Streamable HTTP `POST /mcp` 调用动态工具。
- **富阅读器**：桌面 / 移动端只做文本、动态表单、标注审阅；PDF / Web / Monaco 富渲染按 `docs/05` 结论仍以 Web 端为准。
- **Android**：容器内 `dotnet workload list` 为空，无 Android SDK；`Episteme.Android` 未编译、未打包 APK、未真机运行。
- **桌面 GUI**：容器内无 X server，未实际打开窗口；验证的是编译 + 共享客户端层的真实 HTTP 冒烟。
- **服务端简化**：鉴权仍是 `X-Episteme-Role`；SQLite 单库；未接 PostgreSQL / Redis / MinIO / JWT / HMAC-SHA256 / Nonce / SSE / Quartz；Web 抓取无 SSRF 隔离 worker；MCP 为自实现最小 JSON-RPC，非官方 C# SDK。
- **前端**：原生零依赖 SPA，不是 Blazor；`design/tokens.json` 四套浅色主题由 JS 写入 CSS variables。
- **运行策略**：`restart: "no"`，不开机自启。
- **Git**：本轮产出为本地提交；远端同步到 P3 的 `0064aef`，如要推送需新的认证方式（无持久化凭证）。
